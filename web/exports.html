Como carregar no pandas ↓

Enquanto o RTR estiver rodando, alterações são detectadas a cada 2 segundos e a geração ocorre em segundo plano. Os arquivos locais são substituídos por versões completas; o tempo total depende do tamanho da base. Um arquivo baixado pelo navegador é uma cópia fixa e não se atualiza sozinho.

Vídeos prontos para análise

active_video_metrics.csv: uma linha por vídeo ativo, com as métricas mais recentes, nome do canal e lista de hashtags em JSON. video_metrics.csv: a mesma estrutura, incluindo a lixeira e suas marcações.

Views e curtidas são acumuladas até cada coleta. Para analisar a evolução, use video_snapshots.csv, com todos os registros históricos.

Carregar no pandas

Na pasta principal do RTR, há a pasta analysis, com um carregador que preserva IDs como texto, inteiros e valores ausentes. Dentro de analysis, use:

from rtr_data import load_dataset, load_all

videos = load_dataset("active_video_metrics")
print(videos[["id", "channel_handle", "views", "likes", "duration_seconds"]].head())

# Todas as tabelas da mesma versão, para fazer joins consistentes.
tabelas = load_all()
canais = tabelas["channels"]
historico = tabelas["video_snapshots"]

Requer Python e pandas. Para carregar de outra pasta, adicione a pasta analysis ao caminho de importação. O carregador usa .local/exports/latest.json para localizar uma versão consistente de todos os arquivos. Chame novamente para obter os dados atualizados; um DataFrame já carregado permanece com os valores daquele momento.

Converter para Parquet (opcional)
O servidor gera CSV automaticamente. Se você também quiser Parquet, o conversor incluído exige Python, pandas e pyarrow. Execute na pasta principal do RTR:
python -m pip install pandas pyarrow
python analysis/to_parquet.py --watch
O conversor atualiza o Parquet enquanto permanecer em execução, seguindo as novas versões dos CSVs. A pasta de saída é .local/exports/parquet. Cada geração cria uma pasta própria; latest.json aponta para a última versão completa. Gerações de Parquet são mantidas até você removê-las.


Formato e consistência
CSV em UTF-8, separado por vírgula, com textos entre aspas e datas mantidas como na base. Campos NULL usam um marcador indicado em latest.json, para preservar textos vazios e distinguir ausência de zero. raw_json e tags_json continuam sendo texto JSON; use json.loads para expandir.
Os arquivos diretamente em exports têm nomes fixos. Para cruzar várias tabelas durante uma coleta, use o carregador ou os caminhos de latest.json: eles apontam para uma única leitura consistente do banco. Versões CSV antigas são mantidas por pelo menos 2 minutos e as 3 mais recentes são preservadas. O SQLite continua sendo a fonte principal; editar um CSV não altera o banco.
